## 1. Make the three code-font choices distinguishable

### Diagnosis

The three native select options inherited the same UI font and exposed the same
selection interaction. Only the currently selected pair had a preview. Their
names therefore looked almost interchangeable, despite the bundled font files
being different. All three choices serve the same code-typography function; it
would be misleading to present them as three different editor capabilities.

### Implemented comparison

| Pair | Reading intention | Visible distinction |
| --- | --- | --- |
| JetBrains Mono + Sarasa Gothic SC | Engineering reading | Crisp Latin code and restrained Chinese sans-serif text |
| Fira Code + LXGW WenKai | Chinese comments and tutorials | Latin code paired with a handwritten-style Chinese face |
| Cascadia Code + MiSans | Compact mixed-language reading | Slightly narrower Latin advance and Chinese text consistent with the default UI |

- Replace the code select with three native radio choices. No hidden legacy
  select or duplicate state remains.
- Give every choice its own actual font-family and the same diagnostic sample:
  ambiguous Latin characters, operator ligatures, and Chinese comments.
- Show the reading intention, exact font pair, short explanation, radio state,
  selected border/background, and a current-choice status message.
- Compare all three in one row on desktop; stack them below 700 CSS pixels.
  Use a 16px specimen instead of asking users to compare 12px option labels.
- Keep the body-font selector separate. Its scope is UI and document prose;
  code choices affect source, code blocks, inline code and shortcut keycaps.
- Collapse secondary offline/font information into a disclosure. Keep the
  panel heading, close action and current-choice footer visible while its
  content scrolls.

These are recommendations, not exclusive capabilities. All three Latin fonts
support ligatures. The mixed Chinese/Latin pairs do not promise strict 2:1
character-cell alignment. Font IDs, storage keys, independent preferences and
Markdown content remain unchanged. Additional specimens load when the panel
opens; the application does not preload every font at startup.

Implementation: `src/components/TypographyPanel.tsx`, `src/lib/editorFont.ts`,
and `src/styles/global.css`.

## 2. Smooth transitions without delaying interaction

| Transition role | Duration | Curve / behavior |
| --- | --- | --- |
| Small control feedback | 120ms | Shared ease-out |
| Surface exit | 160ms | Shared ease-in |
| Surface/content entrance and diagram replacement | 220ms | Shared ease-out |
| Outline layout and theme surfaces | 280ms | Shared ease-out |
| Outline navigation and active-tab visibility | Browser-native smooth scrolling | Instant under reduced motion |

Ease-out: `cubic-bezier(0.22, 1, 0.36, 1)`.
Ease-in: `cubic-bezier(0.4, 0, 1, 1)`.
Tokens are defined in `src/styles/global.css`; the diagram reveal reads those
tokens rather than keeping its old independent timing.

### Previously abrupt or unsafe nodes

- Typography, export, search, recent files, dialogs and media previews vanished
  immediately. Shared `Presence` now retains only the exit picture. Logical
  close immediately makes it inert and hidden from accessibility, removes
  focus/keyboard listeners, and blocks duplicate business actions.
- Rapid reopen cancels the removal timer. Search query state and shortcut
  recording reset on close. An old exit cannot later steal another dialog's focus.
- Popovers use a short 6px offset; modal dialogs fade without scaling or jumping.
  Native media dialogs close immediately for input/focus purposes and retain
  only their visual exit using discrete display/overlay transitions.
- Root View Transition snapshots intercepted real pointer hit testing. Remove
  the snapshot manager and its obsolete CSS/tests. Theme changes now update
  live DOM colors, leaving controls and source editing usable throughout.
  Explicit document headings, emphasis, code, table cells and UI color surfaces
  participate; presence transitions retain color transitions rather than
  overwriting them. Initial layout applies the initial theme before paint;
  asynchronous native preference loading remains separate. Preference writes
  stay after the startup read, so a ready native store cannot have its saved
  dark choice overwritten by the initial light state.
- Mermaid keeps the existing decoded preview until its replacement is ready,
  preserves the layout box for a color-only change, and rejects stale results.
  Slow diagrams no longer delay the entire interface.
- Outline navigation previously issued an immediate ProseMirror scroll and
  then a smooth DOM scroll. It now performs one preference-aware scroll.
  Normal editing, selection restoration and draft synchronization stay instant.
- Keyboard tab selection focuses with preventScroll, so moving to an offscreen
  tab does not bypass the tab strip's smooth reveal with a native focus jump.
- Source/rendered and tab changes receive a quiet incoming fade without
  remounting editors or retaining two interactive editing surfaces.
- Remove distracting dirty-state bounce, rotating add-tab feedback, repeated
  search pulse and excessive welcome stagger.

Reduced-motion preferences disable spatial motion and practically eliminate
CSS timing; retained exits unmount immediately. Theme inversion can still have
brief intermediate contrast changes: static endpoint contrast is verified, not
a claim of WCAG contrast compliance for every interpolated animation frame.

Implementation: `src/lib/presence.tsx`, `src/lib/theme.ts`,
`src/lib/useDialogFocus.ts`, `src/lib/mermaid.ts`, `src/App.tsx`, and affected
search, shortcut, media, tab, toolbar and outline components.

## 3. Refine hierarchy, rhythm and responsive layout

- Preserve the established reading system: 16px body, 1.75 line height (28px),
  720px reading column, 16px source and 14px code blocks with 1.6 line height.
  Keep the existing heading scale rather than introducing a new visual identity.
- Standardize UI roles at 16px title, 13px label and 12px supporting text; use
  4/8/12/16/24px spacing tokens and consistent group alignment.
- Tighten spacing between adjacent headings and after horizontal rules, as
  seen in the reference document. Improve paragraph wrapping. Table emphasis
  uses the selected body's real weight, including WenKai Medium 500.
- Use stable scrollbar gutters and themed caret/selection colors. Code and
  long tables retain their own horizontal scrolling instead of widening the app.
- Keep modal actions reachable with viewport-bounded height and independently
  scrolling content. Typography uses two columns for body control/preview and
  three columns for code comparison; both simplify on narrow viewports.
- Preserve the user's outline width at intermediate desktop sizes. Narrow
  outlines animate in both directions rather than disappearing via display:none.
- Put save state before secondary statistics and never hide it at narrow widths.
  Below 520px, use a two-row toolbar instead of clipping editing actions.
- Use dynamic viewport height. The 320px and 390px browser checks are responsive
  stress tests, not a claim that a mobile app ships; the native minimum remains
  800x600 and is not changed.

Implementation: `src/styles/global.css`, `src/styles/document.css`,
`src/components/StatusBar.tsx`. Shared document/export font semantics remain intact.

  No UAC, policy, registry or global environment settings were changed to
