# 2026-11-08 编辑器性能修复

本轮减少了输入事务中的重复遍历、表格序列化和标签切换时的同步解析。保存、立即关闭、图片引用更新、源码撤销和会话位置恢复继续使用原有业务语义。

## 修复范围

1. **输入与 React 更新。** `EditorTab` 只接收它实际使用的稳定 `tabId`、`initialContent`，避免统计或 Markdown 更新触发与编辑视图无关的重新渲染。`SourceEditor` 通过稳定的 `(tabId, text)` 回调明确文稿身份，后台程序化编辑仍然更新对应文稿。统计改为单次 UTF-16 扫描，保持原来的空白、中文、英文单词和行数定义；未改变前缀中的光标映射不再扫描剩余全文。
2. **大表格事务。** 表格对齐插件记住已验证的不可变表格和行，只修正实际变化的单元格，省去逐格位置解析和空追加事务。无图片的顶层表格、行 Markdown AST 和单元格转义文本可以复用；图片 URL 变化仍按当前引用重新序列化。
3. **整篇文稿扫描。** 标题、图片和代码块索引复用不可变子树。Prism 对选区事务直接保留装饰；无关内容变化映射既有装饰；代码块变化、移动或删除仍运行原高亮逻辑。
4. **标签切换。** 点击标签只冻结当前内容、选区与可见位置。既有会话持久化或立即关闭流程消费该快照时，才构造持久化锚点。切换路径不再调用 `remark.parse`，也不再建立整篇源码的测量镜像。每个标签最多保留一个待消费快照，没有新增定时器。
5. **资源打包。** 九个业务字体改为显式引用，阻止目录中的未引用字体、备份或原件进入产物。实际体积原因和 NSIS 测量见[安装包体积报告](package-size-2026-11-08.md)。

没有把 Markdown 发布改成异步防抖。编辑事务返回时，同步内容镜像已经包含最新输入，因此立即保存和关闭仍能读取最新内容。

## 同机浏览器对照

基线来自开始本轮工作时的前端副本，包含用户当时已有的未提交改动，不是 Git HEAD。新旧版本使用同一个前台 Ego Lite 页面、Chromium 156 和同一份测试逻辑。

夹具包含 **1,200 行、5 列**表格、表格前后的段落和一个 TypeScript 代码块，初始 Markdown 为 **70,144 UTF-8 字节**。每个位置输入 10 次，时间包括真实 ProseMirror `dispatch`、插件和同步内容更新，不包括硬件按键、输入法或下一帧绘制。

| 同步事务中位数    |   修改前 |  修改后 |
| ----------------- | -------: | ------: |
| 表格前输入        | 153.3 ms |  3.9 ms |
| 表格内输入        | 154.0 ms | 20.6 ms |
| 表格后输入        | 151.2 ms |  6.2 ms |
| 只移动选区，20 次 |   2.0 ms |  0.5 ms |

表格前、表格内、表格后输入的修改后 p95 分别为 6.5 ms、22.6 ms、8.8 ms。测量值用于对照，不作为依赖机器速度的新增测试门槛。

同一夹具滚动 24 帧直到表格末尾：帧间隔中位数由 5.0 ms 变为 5.1 ms，双方 p95 都是 10.0 ms。**本轮没有测得纯滚动帧率提升。** 已验证滚动不重建文稿、表格行不丢失，输入与选区事务减少的阻塞时间不应被描述成纯滚动性能收益。

表格内输入仍需 GFM 计算整张表的列宽，因此耗时随表格规模增长。没有为了缩短计时改写 Markdown 表格布局、虚拟化可编辑表格或更换编辑器。

对应测试为 `tests/browser/performance.ts`，原始对照为审计目录内的 `ego-foreground-regressions.json`。基线副本仅补入相同测量夹具，业务实现保持原样。

## 正确性与质量检查

- `npm run check` 通过：ESLint、Prettier、配置同步、两套 TypeScript 检查和覆盖率门槛通过，**75 个测试文件、810 项测试通过**。本轮开始时基线为 73 个测试文件、794 项测试通过。
- Rust 格式检查和 `cargo clippy --locked --all-targets -- -D warnings` 通过。`cargo test --locked` 为 **108 passed / 0 failed / 3 ignored**；既有真实符号链接专项另行运行这 3 项，结果 **3 passed / 0 failed / 0 ignored**，共覆盖 111 项不同测试。
- 新增回归对照原 GFM 对齐与 Prism 行为，覆盖行列变更、撤销重做、同一个代码块节点移动、图片引用变化。缓存计数断言确认：500 行表格外输入只序列化一个段落；200 行表格内输入只重建一行。
- 标签测试确认切换时 `remark.parse` 调用为零，包括刚刚编辑后的切换；持久化消费时仍能得到冻结时的内容与位置。真实 12 标签浏览器测试确认选区方向、滚动位置、文稿和 DOM 身份不变，源码立即输入后切换没有串稿。
- 49 项业务浏览器回归通过，覆盖 Markdown 往返、代码高亮、立即保存/关闭、输入期间保存、图片重写、后台焦点、源码历史、会话恢复、图片插入与离线导出。原生 IPC 在这些浏览器夹具中使用内存模拟；原生文件逻辑另由 Rust 测试验证。

完整覆盖率结果为语句 68.37%、分支 61.58%、函数 68.78%、行 70.02%，沿用现有门槛。未下调测试断言或覆盖率阈值。

## 测量环境与保留证据

Ego Lite 最初处于最小化状态，`requestAnimationFrame` 被后台节流；这批帧时间不纳入性能结论。恢复窗口后仍可能出现 `document.hasFocus() === false`。开启当前测试 CDP 会话的焦点模拟后，新旧版本的全部反向选区断言均通过，没有修改生产代码或测试断言来处理环境问题。

`polish-source-outline-large-input` 在 Ego Lite 中触发了超过 1 秒的既有计时门槛，原版本也失败。CPU 采样主要时间位于浏览器原生执行，而不是应用 JavaScript；这不足以把全部延迟归因于 Markdown 解析。项目标准 HeadlessChrome runner 首次当前版本为 1,183 ms 失败，后续复核通过；最终停止其他浏览器及编译负载后，顺序运行当前版本与基线，两者均通过原断言。所有失败和通过记录均保留，不能声称该场景在所有环境中稳定达标。

Rust 首次运行因系统临时目录权限导致夹具创建失败。重跑只为该子进程设置审计目录内的 `TEMP/TMP`，退出后恢复，没有更改系统环境或 ACL。真实符号链接门禁使用项目既有的正常完整性副本脚本，确认执行文件 SHA256 一致。

证据目录：`.audit/editor-performance-20261108-073718/`。其中保留了初始工作区差异、基线副本、原始失败、最终完整检查日志、浏览器 JSON、CPU 采样和 Rust 验证结果。用户开始本轮工作时已有的其他修改未被还原或覆盖。

## 验证边界

本轮没有安装覆盖现有 MDPlus，没有进行原生 WebView2 的输入法、触控板或滚轮硬件验收，也没有运行 Rust LLVM 覆盖率检查。浏览器事务计时不等于用户每次按键到显示的完整延迟。

Prism 包装依赖当前 Milkdown 7.21 的 `MILKDOWN_PRISM$` 插件键；升级相关依赖时需运行原插件对照回归并复核该键。

字体保持原有离线覆盖、字重和导出能力，因此安装包没有减少数十 MB。最新安装器及其源码绑定、包内 EXE 和完整性核验见体积报告。
