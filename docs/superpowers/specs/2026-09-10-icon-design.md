# MDPlus 图标设计与资源架构

本轮优先完成用户要求的图标重设计，目标是降低图标维护复杂度并保留编辑、保存、窗口与文件关联的现有行为。

## 视觉决定

最终采用用户确认的「折线 M＋」：白色圆角底，黑色折线 M 与紧邻其右的等臂加号。图形只由笔画与留白构成，不依赖字体，M 与加号作为整体在画布中居中。16、24、32 像素和大尺寸保留同一标记。

此前的中间方案均已否决：深青绿底、纸页折成 M、薄荷绿加号的「折页 M＋」因彩色底与加号位置未获认可；另两种已比较的方案是文档折角和几何字标，前者在小尺寸包含更多细节，后者与旧方案更接近。

## 代码审查与方案比较

现有 `make_icon.py` 用系统 Segoe 字体、Pillow 与 NumPy 绘图，`IconBrand` 另外手写 SVG 路径，CSS 再次定义图标颜色。小于 40 像素时生成器删除箭头，与大尺寸标记不同。维护文档仍描述已停用的渐变设计和输出文件。

| 方案 | 收益 | 代价 |
| --- | --- | --- |
| 单份 SVG + 已有 Tauri 图标工具（采用） | 应用和桌面共用几何与配色；无新增依赖；矢量源可直接审阅 | 桌面资源仍需在源图更新后重新生成 |
| 继续 Python 绘制 + 手写 React SVG | 可以分别调整像素 | 存在字体和图形依赖，两套图形容易漂移 |
| 只保存多尺寸位图 | 使用直接 | 缺少可维护的源图，后续修改需逐个替换 |

## 资源与边界

- `src/assets/app-icon.svg` 为唯一正式图形源。
- `IconBrand` 保留已有 SVG 属性和 `size` 接口，通过 SVG image 引用源图。
- 浏览器 favicon 引用同一 SVG，由 Vite 处理构建路径。
- `python make_icon.py` 使用 Python 标准库调用本地 Tauri CLI，在临时目录生成后只复制现有六个桌面资源文件；`--output` 支持独立核验。
- 生成器不再提供旧字形与旧配色的切换命令，正式资源只保留选定的品牌设计。
- 不添加依赖，不修改 Rust 命令、文件关联、编辑器状态与保存流程。
- 本轮改动前曾以逐文件 SHA-256 核对无关原有改动保持不变，不暂存或提交；当时的备份与预览材料已随 `icon-preview/` 清理删除。

## 验收

- 六个桌面资源可重新生成，PNG 为透明 RGBA，尺寸为 32、128、256、512；ICO 包含 Tauri 提供的 16、24、32、48、64、256 像素帧；ICNS 可解析。
- 浅色、深色、小尺寸、应用欢迎页和 favicon 都使用相同图形，浏览器无资源加载错误。
- `npm run check`、`npm run build`、`git diff --check` 通过。
- 重复生成时 PNG 和 ICO 逐字节一致；ICNS 的图像块内容一致，但 Tauri 生成的容器块顺序可能不同。不以静态资源验证代替已安装应用或安装包验证。
