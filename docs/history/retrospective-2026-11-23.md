## 3. 跨领域核实结论与来源

完整核实、短引、原文节、日期和限制见[跨领域研究](cross-domain-2026-11-23.md)。检索日期 2026-11-23，初始八个官方 URL 均读正文并 HTTP 200；实际导出发现 MIME 错配后补读 RFC 8081 §4.4.6，最终九个一手来源。摘要、类比与项目实测分开。

- **可靠性／有条件降级**：Google SRE 的过载处理支持“次要能力降级、核心任务保留”的方法类比，适用于 R2 的 STASH_FULL；采纳窄降级与失败矩阵，不照搬服务吞吐／SLO，也不声称磁盘全满仍可写入。
- **并发／过期结果与丢失更新**：React useEffect cleanup 和 RFC 9110 If-Match 分别支持提交旧结果抑制、写入资格核对；沿用已有代次和字节版本，不能把取消 UI 当作取消已发 IPC。Windows ReplaceFileW 并非原子内容 CAS（`src-tauri/src/safe_files.rs:497,541-555`），当前是捕获、后验核对和保留副本，不宣称完全无竞态。
- **人因／状态与防误操作**：WCAG 4.1.3 的无需抢焦点状态消息直接适用于 Web UI；3.3.4 对本地桌面删除是设计类比。采纳明确保存／恢复状态、可见失败下一步与永久删除确认，不为 harmless 最近列表移除新增确认。代码／文案改善不等于全项 WCAG 或真实读屏验收。
- **契约／结构加语义验证**：JSON Schema 支持形状约束，RFC 8259 支持真实表示预算，RFC 8081 直接登记 font/woff2 与 wOF2 签名。采纳现有配置／IPC、跨表示往返与资源类型／字节反例；不引第二份配置或完整文件嗅探平台。结构／成功消息不证明内容完整、图片持久化、字体类型正确或并发关闭安全。
- **可靠性复盘／证据型学习**：Google SRE Postmortem Culture 支持事件、影响、机制、动作与验证记录；用本项目现有档案和有条件短检查，不为单次可解释环境失败增加事故流程，不作人员归责。
